1//! Reconciliation of internal ledger records against external statements
2//!
3//! Reconciliation answers three questions about a period: which transactions agree between the
4//! ledger and the bank, which exist on only one side, and which are probably the same transaction
5//! recorded slightly differently.
6//!
7//! # Shape of the API
8//!
9//! [`ReconciliationEngine`] is pure and synchronous - hand it both sides and it hands back a
10//! [`ReconciliationReport`]. Loading and saving are separate concerns, behind
11//! [`ReconciliationStorage`]; importing statement files is behind [`ExternalDataParser`]. This
12//! crate ships no parser implementations, because statement layouts are specific to each bank and
13//! gateway.
14//!
15//! # Direction conventions
16//!
17//! Both [`LedgerTransaction`] and [`ExternalTransaction`] hold a **positive** amount plus an
18//! [`EntryType`](crate::types::EntryType), matching [`Entry`](crate::types::Entry). Crucially the
19//! external side's direction must be expressed from the *ledger's* point of view: a deposit shows
20//! as a credit on a bank statement but is a debit in the ledger's bank account. Flipping that sign
21//! is the importer's job, and getting it wrong will make everything look unmatched.
22//!
23//! # How matching works
24//!
25//! 1. **Reference numbers.** A shared UTR, RRN or cheque number backed by an equal amount and
26//!    direction is conclusive, whatever the dates say. Ambiguous references are skipped.
27//! 2. **Exact agreement** on date, amount and direction, resolved through a hash index.
28//! 3. **Scoring.** Everything left over is scored across amount, date, description, direction
29//!    and reference (weighted by [`ScoringWeights`]).
30//! 4. **Best-first assignment.** Scored pairs are assigned highest first, so a weak pairing
31//!    cannot claim a counterpart that a stronger one wanted.
32//! 5. **Suggestions.** Whatever is still unmatched is reported with its closest available
33//!    counterparts, so a person can finish the job.
34//!
35//! Thresholds live in [`ReconciliationConfig`]. The result is independent of the order of either
36//! input vector.
37//!
38//! # Example
39//!
40//! ```
41//! use accounting_core::reconciliation::{
42//!     ExternalSource, ExternalTransaction, LedgerTransaction, ReconciliationConfig,
43//!     ReconciliationEngine,
44//! };
45//! use accounting_core::EntryType;
46//! use bigdecimal::BigDecimal;
47//! use chrono::NaiveDate;
48//!
49//! let booked = NaiveDate::from_ymd_opt(2024, 11, 15).unwrap();
50//! let settled = NaiveDate::from_ymd_opt(2024, 11, 16).unwrap();
51//! let source = ExternalSource::BankStatement {
52//!     bank_name: "SBI".to_string(),
53//!     account_number: "12345678901".to_string(),
54//! };
55//!
56//! // Booked a day before the bank settled it, but both carry the same UTR.
57//! let ledger = vec![LedgerTransaction::new(
58//!     "txn-1".to_string(),
59//!     booked,
60//!     BigDecimal::from(1000),
61//!     "Payment from Acme Ltd".to_string(),
62//!     EntryType::Debit,
63//!     "bank".to_string(),
64//! )
65//! .with_reference("UTR12345")];
66//!
67//! let external = vec![ExternalTransaction::new(
68//!     "ext-1".to_string(),
69//!     settled,
70//!     BigDecimal::from(1000),
71//!     "NEFT/ACME LTD/UTR12345".to_string(),
72//!     EntryType::Debit,
73//!     source.clone(),
74//! )
75//! .with_reference("UTR12345")];
76//!
77//! let engine = ReconciliationEngine::new(ReconciliationConfig::default());
78//! let report = engine.reconcile(&ledger, &external, source);
79//!
80//! assert_eq!(report.matched_count, 1);
81//! assert!(report.is_fully_reconciled());
82//! ```
