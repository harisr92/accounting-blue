1//! Reconciliation of internal ledger records against external statements
2//!
3//! Reconciliation answers three questions about a period: which transactions agree between the
4//! ledger and the bank, which exist on only one side, and which are probably the same transaction
5//! recorded slightly differently.
6//!
7//! # Shape of the API
8//!
9//! [`ReconciliationEngine`] is pure and synchronous - hand it both sides and it hands back a
10//! [`ReconciliationReport`]. Loading and saving are separate concerns, behind
11//! [`ReconciliationStorage`]; importing statement files is behind [`ExternalDataParser`]. This
12//! crate ships no parser implementations, because statement layouts are specific to each bank and
13//! gateway.
14//!
15//! # Direction conventions
16//!
17//! Both [`LedgerTransaction`] and [`ExternalTransaction`] hold a **positive** amount plus an
18//! [`EntryType`](crate::types::EntryType), matching [`Entry`](crate::types::Entry). Crucially the
19//! external side's direction must be expressed from the *ledger's* point of view: a deposit shows
20//! as a credit on a bank statement but is a debit in the ledger's bank account. Flipping that sign
21//! is the importer's job, and getting it wrong will make everything look unmatched.
22//!
23//! # How matching works
24//!
25//! 1. **Reference numbers.** A shared UTR, RRN or cheque number backed by an equal amount and
26//!    direction is conclusive, whatever the dates say. Ambiguous references are skipped.
27//! 2. **Exact agreement** on date, amount and direction, resolved through a hash index.
28//! 3. **Scored pairing.** Everything left over is scored across amount, date, description,
29//!    direction and reference, then assigned best-first so a weak pairing cannot claim a
30//!    counterpart that a stronger one wanted.
31//! 4. **Suggestions.** Whatever is still unmatched is reported with its closest available
32//!    counterparts, so a person can finish the job.
33//!
34//! Thresholds live in [`ReconciliationConfig`]. The result is independent of the order of either
35//! input vector.
36//!
37//! # Example
38//!
39//! ```
40//! use accounting_core::reconciliation::{
41//!     ExternalSource, ExternalTransaction, LedgerTransaction, ReconciliationConfig,
42//!     ReconciliationEngine,
43//! };
44//! use accounting_core::EntryType;
45//! use bigdecimal::BigDecimal;
46//! use chrono::NaiveDate;
47//!
48//! let booked = NaiveDate::from_ymd_opt(2024, 11, 15).unwrap();
49//! let settled = NaiveDate::from_ymd_opt(2024, 11, 16).unwrap();
50//! let source = ExternalSource::BankStatement {
51//!     bank_name: "SBI".to_string(),
52//!     account_number: "12345678901".to_string(),
53//! };
54//!
55//! // Booked a day before the bank settled it, but both carry the same UTR.
56//! let ledger = vec![LedgerTransaction::new(
57//!     "txn-1".to_string(),
58//!     booked,
59//!     BigDecimal::from(1000),
60//!     "Payment from Acme Ltd".to_string(),
61//!     EntryType::Debit,
62//!     "bank".to_string(),
63//! )
64//! .with_reference("UTR12345")];
65//!
66//! let external = vec![ExternalTransaction::new(
67//!     "ext-1".to_string(),
68//!     settled,
69//!     BigDecimal::from(1000),
70//!     "NEFT/ACME LTD/UTR12345".to_string(),
71//!     EntryType::Debit,
72//!     source.clone(),
73//! )
74//! .with_reference("UTR12345")];
75//!
76//! let engine = ReconciliationEngine::new(ReconciliationConfig::default());
77//! let report = engine.reconcile(ledger, external, source);
78//!
79//! assert_eq!(report.matched_count, 1);
80//! assert!(report.is_fully_reconciled());
81//! ```
